# 去中心化辅种方案（征求意见稿）

> 状态：**想法阶段，尚未实现**，欢迎任何意见，尤其是“哪里不靠谱”“站长会不会接受”“用起来麻不麻烦”。
> 日期：2026-11-05

---

## 一、先用一分钟讲清楚：辅种是什么？

你在 A 站下载了一部电影，正在做种。B 站也有**一模一样**的这部电影。

既然你硬盘里已经有完整的文件，就可以直接去 B 站下载它的种子，让下载器“认出”这些文件已经齐全，**不用重新下载一个字节**，马上开始在 B 站做种、赚上传和魔力值。这就叫**辅种**。

难点只有一个：**怎么知道 B 站的哪个种子和我硬盘里的文件一模一样？**

---

## 二、现在大家是怎么做的？有什么问题？

| 方式 | 怎么做 | 问题 |
|---|---|---|
| **IYUU 等中心化工具** | 把你所有种子的“指纹”上传到一个中心服务器，服务器告诉你其他站有没有 | 中心服务器知道你**在哪些站有账号**、**硬盘里有什么**；服务器一停，大家一起停；需要站点和它合作 |
| **站点自己提供查询接口**（如 NexusPHP 的 pieces-hash 接口） | 你拿指纹去每个站逐个问 | 只能查“分块大小完全相同”的种子，别人发种时分块大小选得不一样就查不到；而且很多站没有这个接口 |
| **按名称搜索再比对**（如海外的 cross-seed） | 按片名去各站搜，把搜到的种子都下载下来比对文件 | 对站点压力大，要下载大量没用的种子文件 |

---

## 三、我们的想法：用户之间“悄悄地、加密地”互相告诉

一句话版本：

> **持有同一份文件的用户之间，直接点对点加密交流“这份文件在哪个站是哪个种子”。只有同样有这份文件、同样有那个站账号的人，才能得到答案。**

不需要中心服务器知道任何事情，也不需要站点把种子目录交出来。

### 打个比方

想象一个**没有名单的暗号俱乐部**：

1. 你手里有一本书（硬盘里的文件）。
2. 你在门口喊书的“暗号”（由文件算出来的指纹），**只有手里也有这本书的人**才听得懂、才会回应你。
3. 对方会**当场考你**：“第 238 页第 5 行写的是什么？”——你必须真的有这本书才答得出来（**证明你真的有文件**，而不是只知道书名）。
4. 你想打听“B 站有没有这本书”，对方会**先确认你确实是 B 站会员**才告诉你，而且答案是用只有 B 站会员才打得开的锁锁住的。
5. 整个对话是**加密**的，帮你们传话的中间人（中继）只看到一堆乱码。

## 四、整个流程长什么样？

```
你的电脑                                               别人的电脑
┌──────────────┐                                    ┌──────────────┐
│ qBittorrent  │                                    │ qBittorrent  │
│ Transmission │                                    │ Transmission │
│      ↕       │                                    │      ↕       │
│  辅种小助手   │ ◄═══════ 加密直连（打洞）═══════► │  辅种小助手   │
└──────┬───────┘     连不上时：经中继转发（仍加密）    └──────┬───────┘
       │                                                    │
       └──────────►  会合点（Cloudflare 免费服务）  ◄────────┘
                    只负责“帮你们找到对方、牵线搭桥”
                    看不到你们聊了什么、是哪个站、什么片
```

**“辅种小助手”** 是装在你自己电脑（或 NAS、盒子）上的一个小程序，它连接你本地的 qB / TR，做以下事情：

1. **读取**下载器里已经 **100% 完成**的种子，算出文件指纹。
2. **去会合点找人**：找到同样持有这份文件的其他小助手。
3. **加密握手 + 互相考试**：双方都证明自己真的有这份文件。
4. **交换站点信息**：只交换双方**都有账号**的站点上的种子编号。
5. **自己去站点下载种子**（用你自己的账号），**完整校验 100% 通过才开始做种**，校验不通过就删掉，绝不下载任何数据。

## 五、什么样的种子才会被辅种？（规则先说死）

只有同时满足以下条件才辅种：

1. **种子总大小一致**；
2. **种子里的文件结构一致**：文件数量、每个文件的路径和名称、每个文件的大小、顺序都一样（最外层文件夹名字不同没关系，小助手会自动处理）；
3. 加入下载器后**完整校验必须 100% 通过**。

以下情况**不会**辅种：

- 重新压制、换了封装、修复版（PROPER/REPACK）——内容不一样；
- 音乐改过标签、换过封面——哪怕大小没变，校验也过不了，会自动放弃；
- 少了或多了文件（哪怕只是一个 nfo）——结构不一样；
- 你本地还没下载完的种子。

> 为什么这么严格？因为辅种的本意是“零下载做种”。只要需要下载哪怕一点点，那就是下载，不是辅种，也会牵扯到 H&R 考核等问题。

## 六、隐私和安全：谁能看到什么？

这是大家最关心的部分。

### 两条铁律

1. **端到端加密**：所有交流只有对话双方能看懂。会合点、中继、网络运营商看到的都是乱码。
2. **不向没有账号的人泄露任何站点信息**：
   - 你只能查询**你自己电脑里真实存在的文件**（会被现场“考试”验证）；
   - 你只能得到**你自己配置了账号的站点**的信息（会被验证是不是该站会员）。

### 各方能看到什么

| 谁 | 能看到 | 看不到 |
|---|---|---|
| **会合点（Cloudflare）** | 一些看不懂的随机编号、你的 IP | 你有什么文件、在哪些站、和谁说了什么 |
| **中继（连不上时才用）** | 一堆加密数据、双方 IP | 加密数据里的任何内容 |
| **和你对话的另一个用户** | 你们**共同拥有**的那份文件；你们**共同所在**的站点上这份文件的种子编号 | 你的其他文件、你在其他站的账号 |
| **没有这份文件的人** | 什么都看不到（握手都完成不了） | — |
| **有文件但不是某站会员的人** | 看不到那个站的任何信息 | — |
| **PT 站点** | 你下载了它的哪个种子（这和平时手动下载种子完全一样） | 你在别的站有什么 |

### “怎么证明对方是某站会员”？分两种情况

| 站点类型 | 证明方式 | 靠谱程度 |
|---|---|---|
| **愿意配合的站点**（比如使用 PT Studio 的站点） | 站点每周给会员发一把“会员钥匙”，信息用这把钥匙加密，不是会员根本打不开；被封号的人下周就拿不到新钥匙 | **非常靠谱**（密码学保证） |
| **不配合的站点**（没有加任何接口的老站） | 对方随机挑一个他在该站的种子编号，让你用自己的账号下载并报出种子的特征值，答对才算会员 | **尽力而为**：能证明你此刻能从该站下载种子，但挡不住会员把种子文件私下转给别人 |

## 七、中继能用 Cloudflare 的免费服务吗？（已调研）

大部分情况下两台电脑可以通过“打洞”直接连上；遇到严格的网络（比如公司网络、部分运营商的大内网）连不上时，才需要中继帮忙转发。

我们查了 Cloudflare 官方文档，有两种免费可用的选择：

| 方案 | 免费额度 | 超出后 | 优点 | 缺点 |
|---|---|---|---|---|
| **Cloudflare Realtime TURN**（专业的中继服务） | 每月 **1000 GB** 免费流量；打洞用的 STUN 服务**完全免费、不限量** | 每 GB 0.05 美元 | 专为点对点中继设计，全球就近接入；单个连接 50–100 Mbps，足够用 | 超出会**产生费用**；凭证需要由会合点签发（有效期可设置）；**Cloudflare 的中国网络不提供该服务，国内用户会连到境外节点**，延迟和可用性要实测 |
| **Cloudflare Workers + Durable Objects**（自己写一个简单转发器） | 免费版每天 **10 万次请求**；转发的消息按“20 条算 1 次”计算；还有每天 13,000 GB·秒的运行时长 | 免费版**超出直接报错，不会扣费** | 永远不会产生意外账单；和会合点放在一起，部署简单 | 额度比 TURN 小，但我们传的只是很小的文字信息，按每次辅种查询约 20 条消息估算，每天能支撑约 10 万次查询 |

**我们的建议：**

- **打洞**：使用 Cloudflare 免费 STUN（`stun.cloudflare.com`）。
- **中继默认**：用 Workers + Durable Objects，**额度用完就停，不会扣钱**。
- **TURN 作为可选项**：给有需要的社区部署者打开。
- **允许社区自建中继**：任何人都可以搭一个中继节点（比如国内服务器），小助手可以配置多个中继，谁快用谁。

> 我们传输的只是“哪个站、哪个种子编号”这种几十字节的小信息，**不会经过中继传输任何电影文件**，所以免费额度绰绰有余。
> 中继本身看不到内容：TURN 只负责转发数据包，加密由我们自己在上层完成；Cloudflare 文档也明确说明 TURN 本身不负责端到端加密，需要上层协议来做，我们正是这么设计的。

## 八、可能的风险，以及我们怎么应对

| 风险 | 应对 |
|---|---|
| **有人发假信息**（告诉你一个错误的种子编号） | 小助手下载种子后会先比对结构，再完整校验，不对就删除，不会损坏你的文件，最多浪费一次种子下载；经常给假信息的对象会被自动拉黑 |
| **有人疯狂发请求骚扰** | 不知道文件指纹连握手都完成不了；“考试”需要真实读硬盘；每个人每天的应答次数有上限 |
| **直连会暴露 IP** | 提供“只走中继”的隐私模式，由你自己选择 |
| **某个站的会员钥匙被泄露** | 钥匙每周更换，领取钥匙有频率限制和记录 |
| **Cloudflare 封号或服务不可用** | 会合点和中继的程序都开源，任何人都能重新部署，小助手可以配置多个 |
| **违反某些站点的规则** | 小助手会读取站点公开的策略声明，**站点声明不允许的，一律不参与**；默认只在你明确开启的站点上工作 |

## 九、对站长来说意味着什么？

- **不需要交出种子目录**，也不需要和任何第三方合作；
- 不会有人能批量拉取你的站点资源列表——只有真正持有文件、并且是你站会员的人，才能得到你站的种子编号；
- 辅种用户的种子都是用他自己的账号、从你的站正常下载的，统计、魔力、做种奖励都和平时一样；
- 想更安全，可以开启“会员钥匙”功能（PT Studio 会内置，其他站点程序也可以按公开规范实现）；
- 不想参与，发一个“不允许”的声明即可，小助手会遵守。

## 十、常见问题

**问：我要做什么？**
答：在 NAS / 盒子上运行“辅种小助手”，填上下载器地址和你各站的账号信息即可，其他自动完成。

**问：我的账号、passkey 会被发给别人吗？**
答：**不会**。账号信息只保存在你自己的设备上，只用于你自己去站点下载种子。

**问：会不会因为辅种被判作弊？**
答：辅种是真实做种，上传都是真实的。我们也会提醒站点的反作弊规则对“刚加入就是做种状态”的情况做好兼容。另外小助手**永远不会跳过校验**，跳过校验在很多站是明令禁止的。

**问：新发布的种子能马上辅种吗？**
答：取决于有没有其他人已经同时拥有这份文件和那个站的种子。用的人越多，覆盖越全，前期覆盖率会比较低。

**问：和 IYUU 能一起用吗？**
答：可以，互不冲突。
