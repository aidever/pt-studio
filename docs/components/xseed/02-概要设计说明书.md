## 1. 设计目标与原则

### 1.1 需求基线

本组件没有单独的需求规格说明书，下表即需求基线，供 §8 追溯。

| 编号 | 需求 | 优先级 |
|---|---|---|
| FR-XSP-001 | 读取本机下载器（qBittorrent、Transmission）中 100% 完成的种子，计算结构指纹、内容指纹 | P0 |
| FR-XSP-002 | 辅种判定：去掉填充文件和根目录名后，文件列表（规范化相对路径、大小、顺序）完全一致；单文件种子还要求文件名一致 | P0 |
| FR-XSP-003 | 发现同样持有该内容的其他设备，不依赖中心服务器保存目录或资源库 | P0 |
| FR-XSP-004 | 端到端加密，节点不能读取或篡改会话内容 | P0 |
| FR-XSP-005 | 只对“持有该内容数据”且“证明是该站会员”的对端透露该站种子信息（三道锁） | P0 |
| FR-XSP-006 | 抵抗中间人中转挑战（通道绑定） | P0 |
| FR-XSP-007 | 未通过验证的对端拿不到本机 IP；通过验证后才允许直连；用户可选择永不暴露 IP | P0 |
| FR-XSP-008 | 种子来源：优先使用对端发来的去凭证种子并换上本机 announce 地址；失败时用本机账号从站点下载；结果按 tracker 记住 | P0 |
| FR-XSP-009 | 信任本机下载器状态，以跳过校验的方式加种；只有结构一致时按首尾分块抽查 | P0 |
| FR-XSP-010 | 下载器操作安全：不删数据、不移动数据、只操作自己加入的种子、幂等 | P0 |
| FR-XSP-011 | 站点识别：站点定义库（首版从 PT-depiler 导入）+ 按 tracker 主机匹配，支持多 tracker | P0 |
| FR-XSP-012 | 站点特性（种子来源、下载地址、scrape 支持）先试后回退、本机记住，可导出 | P1 |
| FR-XSP-013 | 节点由任何人提供，经注册中心登记；按桶水平扩展；节点之间不同步数据 | P0 |
| FR-XSP-014 | 注册中心内容由所有者离线签名，客户端定时拉取并验签 | P0 |
| FR-XSP-015 | 站点侧（PT Studio）提供会员群组密钥与策略声明 | P1 |
| FR-XSP-016 | 试运行模式、Web UI、审计日志 | P1 |
| FR-XSP-017 | 可选 Tor 传输（SOCKS5；内嵌 arti 为 P2） | P2 |
| NFR-XSP-001 | 单节点 1 vCPU / 1 GiB 内存承载 ≥ 1 万台在线设备 | P0 |
| NFR-XSP-002 | 每次交换经节点转发的流量 ≤ 8 KiB（直连成功时） | P0 |
| NFR-XSP-003 | 小助手空闲时内存 < 60 MiB；支持 amd64 / arm64 | P1 |
| NFR-XSP-004 | 指纹计算、结构比对、加种（内容 hash 已证明一致时）读盘量为 0 | P0 |
| NFR-XSP-005 | 节点、注册中心可在 24 小时内整体迁移，不丢失需要迁移的数据（全部为软状态） | P0 |

### 1.2 设计原则

1. **无全局目录。** 任何一方都不持有“谁有什么”的完整视图：索引节点只见桶号，信箱节点只见 IP，对端只见双方共有的内容与共同站点。
2. **先验证、后暴露。** IP、站点种子信息、info_hash 都只在对应的锁通过后发送。
3. **零信任节点。** 节点作恶最多造成拒绝服务；机密性和完整性由端到端密码学保证，不依赖节点的诚实。
4. **软状态。** 节点上的全部状态都可以丢失，由客户端周期性重建；节点之间不复制数据。
5. **本机为准。** 判断内容是否一致、能否加种，以本机下载器状态和本机读到的数据为准，不信任对端的声明。
6. **失败安全。** 任何一步不确定就放弃这一条，不下载数据、不改动已有种子和文件。
7. **协议与传输分离。** 会话协议是不依赖 I/O 的状态机（sans-IO）；节点中继、QUIC 直连、Tor 只是可替换的传输层。

### 1.3 非目标

部分辅种；跨文件系统复制数据；保护 BT 数据传输本身的匿名性（做种时 tracker 和对端本来就能看到 IP）；Deluge / rTorrent 适配（v2）；I2P。

## 2. 总体结构

### 2.1 部署视图

```
                         ┌──────────────── xseed-registry（GitHub 仓库）────────────────┐
                         │ nodes/*.yaml  sites/*.yaml  traits/*.yaml                     │
                         │ 所有者本机：xseed-registry publish → index.cbor + .minisig     │
                         │ Actions：只同步到 Releases / Pages / jsDelivr（不接触私钥）     │
                         └───────────────────────────────┬──────────────────────────────┘
                                                         │ HTTPS 拉取 + 验签（6 h）
 ┌──────────── 用户设备 A ────────────┐                   │                 ┌──────────── 用户设备 B ────────────┐
 │ qB / TR ◄── WebUI/RPC ──► agent ───┼── WSS ──► 节点 HA（信箱）           │ agent ◄── WebUI/RPC ──► qB / TR    │
 │                       │  ▲         │            │   ▲   │ /v1/fwd       │   ▲                                 │
 │                       │  │ QUIC 直连（锁全部通过后）─┼───┼───┼──────────────┼───┘                                 │
 │                       ▼  │         │            │   │   └──────► 节点 HB（信箱）◄── WSS ── agent             │
 │                 PT 站点（仅回退）    │            │   │                    │                                     │
 └────────────────────────────────────┘            ▼   │                    └─────────────────────────────────────┘
                                         节点 I1、I2（桶索引，HRW 选出，R=2）
                                         登记/查询经 HA 两跳转发，HPKE 加密到 I1/I2
```

| 组件 | 部署者 | 形态 | 状态 |
|---|---|---|---|
| `xseed-agent` | 用户（NAS / 盒子 / PC） | Rust 单文件二进制、Docker（amd64 / arm64），内置 Web UI | SQLite（凭证加密） |
| `xseed-node` | 任何人 | Rust 单文件二进制；角色 `home`（信箱、信令、中继）、`index`（桶索引）可分别开启 | 内存软状态；优雅退出时可选快照 |
| `xseed-node-cf` | 项目官方（P2） | workers-rs 包装 `xseed-core`，Worker + Durable Objects | 同上 |
| `xseed-registry` | 所有者 | GitHub 仓库 + 发布 CLI | Git |
| `crossseed-api`（扩展） | PT Studio 站点 | 现有 WASM 插件新增路由 | 站点主密钥 |

## 5. 关键流程

### 5.1 登记（两跳）

```
agent A          节点 HA（home）              节点 I（index，HRW 选出）
  │ 按 HRW 把本机桶集合分到各 index 节点
  │ req = HPKE.Seal(pk_I, REGISTER{reg_id, mailbox_addr, buckets, pow})
  │── POST /v1/ohttp {target=I, req} ─►│
  │                                    │── POST /v1/gateway {req} ─►│  解封装、校验 pow、替换 reg_id 的旧集合
  │                                    │◄── HPKE 封装的响应 ─────────│
  │◄── 响应 ───────────────────────────│
```

HA 知道 A 的 IP，但看不到桶；I 看得到桶，但只知道 HA 的 IP。HA 恰好也是这些桶的 index 节点时，改由另一个 home 节点转发（§DD-XSP-3）。

### 5.2 查询、探测与会话

```
A（查询方）            HA                    HB                   B（应答方）
 │ LOOKUP(bucket) 两跳 → I1、I2，得到 [mailbox_addr…]
 │─ PROBE{bucket, nonce, tag=HMAC(Kprobe(SFP), …), reply_to} ─► HA ─/v1/fwd─► HB ─WS─► B
 │                                                                    B：在该桶的本机内容中逐一校验 tag
 │◄──────────────────────────── PROBE_ACK{sid} ◄──────────────────────│（不匹配则静默）
 │═══ Noise XXpsk3（psk = HKDF(SFP)），3 条消息，全部经 HA ⇄ HB 转发 ═══│
 │═══ 锁 2：双向持有证明（答案绑定握手 hash h）═══════════════════════│
 │═══ 锁 3：群组密钥报价 / 声明共同 tracker + scrape 或下载挑战 ═════════│
 │═══ 报价元数据（站点、info_hash、种子编号）═══════════════════════════│
 │═══ UPGRADE：交换直连候选地址与证书指纹（经 Noise 通道）════════════════│
 │◄────────────── QUIC 直连（证书钉扎）：传输清洗后的种子 ──────────────►│
 │                打洞失败或任一方 ip_exposure=never：经 HA ⇄ HB 分块中继
 │═══ DONE ═══════════════════════════════════════════════════════════│
```

### 5.3 加种任务

```
offer ─► 取种（对端种子 + 本机 announce │ 回退：站点下载）
      ─► 校验（info_hash == 声明值，SFP == 本机）
      ─► 内容已证明一致？是：跳过 │ 否：首尾分块抽查
      ─► 布局（复用原路径 │ 硬链接 │ reflink │ 跨文件系统则放弃）
      ─► 加入下载器（停止状态、跳过校验、autoTMM=false、tag=xseed）
      ─► 检查状态（missingFiles / error → 移除，不删文件）
      ─► 随机延迟 0–10 min 启动 ─► 观察 tracker（unregistered → 移除并回退或作废）
      ─► 做种中
```

### 5.4 注册中心发布

```
所有者本机：编辑 nodes/ sites/ traits/ ─► xseed-registry publish
  ├─ 校验清单 schema、节点 /.well-known 签名挑战
  ├─ 生成 index.cbor（version = 上一版 + 1）
  ├─ minisign 签名（私钥只在本机）
  └─ git push ─► Actions 同步到 Releases / Pages / jsDelivr
agent：拉取 ─► 验签（内置主、备公钥）─► version 必须递增 ─► 原子替换
```

## 6. 设计决策

| 编号 | 问题 | 备选方案 | 结论 | 理由 |
|---|---|---|---|---|
| DD-XSP-1 | 怎么发现持有者 | ① 中心目录 ② 全量索引分发 ③ BitTorrent DHT（BEP 44）④ 按桶的分布式索引 | ④ | ① ② 违反“无全局目录”；③ 单值、可被覆盖、记录暴露给任意 DHT 节点；④ 只暴露 16 位前缀，k-匿名，节点可以水平扩展 |
| DD-XSP-2 | 桶怎么分到节点 | 一致性哈希环、HRW | 加权 HRW，R=2 | 不需要虚拟节点；增删节点平均只移动 1/N；权重直接对应节点容量 |
| DD-XSP-3 | 防止 IP 和桶被同一方关联 | 直连 index、Tor、两跳 | HPKE 两跳（OHTTP 式），Tor 可选 | 要关联 IP 和桶，需要 home 与 index 两个节点合谋；无需额外基础设施；国内可用 |
| DD-XSP-4 | 会话加密 | TLS、Noise IK、Noise XXpsk3 | Noise XXpsk3，临时静态密钥 | 没有长期身份，会话之间不可关联；psk 由指纹派生，不知道指纹就无法完成握手，实现锁 1 |
| DD-XSP-5 | 防挑战被中间人中转 | 无、通道绑定 | 所有锁答案对握手 hash `h` 做 HMAC | 中间人两侧的 `h` 不同，答案无法转用；中间人没有 passkey 或群组密钥，也算不出答案 |
| DD-XSP-6 | 直连与 IP 暴露 | 始终直连、始终中继、验证后直连 | 验证后直连，可配置为从不直连 | 通过锁 3 的对端是同站会员，本来就能从 tracker 拿到 IP；节点流量降为每次几 KiB（NFR-XSP-002） |
| DD-XSP-7 | 种子来源 | 只用本机拼装、只从站点下载、对端原版种子 + 回退 | 对端原版种子（白名单清洗）+ 回退到站点下载 | 保留站点写入种子的其他信息；无站点负载；遇到按种子生成密钥的站点能自动回退 |
| DD-XSP-8 | 加种校验 | 全量校验、跳过校验 | 信任本机状态 + 跳过校验；只有结构一致时做首尾抽查 | 内容 hash 一致时，数据已按同一组 hash 校验过；常见的“结构相同、内容不同”（改标签、改 nfo）改动集中在文件首尾 |
| DD-XSP-9 | scrape 结果的容差与通道绑定 | 明文比较、量化后 HMAC、窗口 HMAC | 窗口 HMAC（d−2…d+2 共 5 个） | 允许 ±2 的时间漂移，同时保留通道绑定；不泄露具体数值 |
| DD-XSP-10 | 消息编码 | JSON、Protobuf、CBOR | 确定性 CBOR | 紧凑；`wasm32` 可用；无需代码生成 |
| DD-XSP-11 | 节点状态 | 数据库、内存软状态 | 内存软状态 + 优雅退出快照 | 节点可以随时替换；1 万台设备的索引约 200 MiB |
| DD-XSP-12 | 注册中心信任 | GitHub 本身、CI 签名、所有者离线签名 | 所有者离线签名（minisign），客户端内置主备公钥 | GitHub 账号被盗或镜像被篡改也伪造不了签名 |
| DD-XSP-13 | 中继 | Cloudflare TURN、节点自身 | 节点自身 | TURN 超额计费；中继流量已降为每次几 KiB |
| DD-XSP-14 | 节点实现 | 原生与 Cloudflare 分别实现、共享核心 | 共享 `xseed-core` + 两个外壳 | 协议逻辑只维护一份 |
| DD-XSP-15 | 站点特性维护 | 人工、自动学习 + 发布 | 本机先试后回退并记住；导出后由所有者发布 | 不需要人工逐站标注；不自动上传，保护隐私 |
